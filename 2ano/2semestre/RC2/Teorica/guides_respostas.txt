1. IGP Routing (RIP & OSPF)
  (Arquivo: 1_IGPRouting_RCII_2026.pdf)

  Exemplo 1 (RIP) - Página 33
  Cenário: Redes configuradas com RIPv2 e split-horizon. HostID = número do router.
   * a) Tabela de Encaminhamento de R3:
       * Diretamente ligadas (C): 192.2.35.0/24, 198.2.20.0/24, 198.1.34.0/24.
       * Remotas (R):
           * 192.1.14.0/24: via R1 (198.1.34.1 ou 198.2.20.1) [Métrica 1].
           * 198.1.2.0/24: via R1 (198.1.34.1 ou 198.2.20.1) [Métrica 1].
           * 198.2.4.0/24: via R4 (198.1.34.4) [Métrica 1].
           * 192.3.66.0/24: via R1 (->R2) ou R4 (->R2) [Métrica 2].
   * b) Vetor de Distância anunciado por R4 para a rede 198.1.34.0/24:
       * Devido ao split-horizon, R4 não anuncia o que aprendeu por essa interface.
       * Anuncia: 198.2.4.0/24 (Met. 1), 192.3.66.0/24 (Met. 2), 198.1.2.0/24 (Met. 2).
   * c) Configuração de R2 para não enviar mensagens RIP em 192.3.66.0/24:
       * Utilizar o comando passive-interface na interface ligada a essa rede.
   * d) Falha na interface de R3 para 198.1.34.0/24 (Tabela de R4):
       * R4 deixa de chegar a R3 diretamente. Para chegar a 192.2.35.0/24, o novo caminho será via R1: R4 -> R1 -> R3. Métrica passa a 2.

  Exemplo 2 (OSPF) - Página 62
  Cenário: R3 não corre OSPF em todas as redes. R2 anuncia rota externa E1.
   * a) Entradas OSPF em R3:
       * R3 aprende via OSPF as redes: 192.1.14.0/24 (Custo 2), 198.1.2.0/24 (Custo 2), 198.2.4.0/24 (Custo 1 via R4), 192.3.66.0/24 (Custo 3), e a rota externa 192.2.35.0/24 (E1, Custo 7 = 2 interno + 5
         externo).
   * b) Entradas OSPF em R2:
       * Conhece as redes internas de R1 e R4. Para 198.1.34.0/24, o custo via R4 é 2 (1+1).
   * c) Sequência de routers no Ping R4 -> 192.2.35.0/24:
       * Request: R4 -> R2 (ASBR).
       * Reply: R2 -> R4. (R2 anuncia a rede, logo o tráfego externo passa por ele).

  2. VLANs
  (Arquivo: 2_VLANs_RCII_2026.pdf)

  Exemplo - Página 21
   * a) Switch que encaminha cada VLAN:
       * VLAN 13 (Local): Sw2 (Switch de distribuição onde a VLAN está confinada).
       * VLAN 35 (Local): Sw4.
       * VLAN 24 (End-to-End): Sw1 (Core Switch, seguindo o modelo de routing distribuído).
   * b) Todos os switches têm de ser L3?
       * Não. Apenas Sw1, Sw2 e Sw4 precisam de capacidades L3 para fazer o routing das suas respetivas VLANs e da VLAN de interligação (VLAN 10). Sw3 poderia ser L2.
   * c) Tabela de Sw2 (RIPv2):
       * 192.13.7.0/24 (C), 192.10.1.0/24 (C).
       * Aprende por RIP: 192.24.2.0/24 via Sw1, 192.35.3.0/24 via Sw4 e Default Route via Sw1.

  3. Spanning Tree (STP/PVST)
  (Arquivo: 3_SpanningTrees_RCII_2026Final.pdf)

  Exemplo - Página 24
   * a) Root Bridge da VLAN 35:
       * Menor BID (Prioridade 1024 + Menor MAC). Entre Sw4 e Sw5, ganha o Sw4.
   * b) Interfaces bloqueadas na VLAN 24:
       * Com Sw4 como Root: Sw3:e1 (ligação ao Sw1) e Sw3:e2 (ligação ao Sw2) são bloqueadas para evitar ciclos, pois Sw3 tem a prioridade mais alta (4096).
   * c) Percurso ICMP Request VLAN 13 -> VLAN 35:
       * PC (VLAN 13) -> Sw4 -> Sw2 -> Sw1 (Routing L3) -> Sw2 -> Sw4 -> Sw5 -> PC (VLAN 35).
   * d) Mudança de estado se Sw1 Prioridade = 4096:
       * Sw1 e Sw3 passam a ter a mesma prioridade. O critério de desempate passa a ser o MAC. Como Sw3 tem MAC menor que Sw1 (...:61 vs ...:f2), Sw3 passa a ser o bridge designado no link Sw1-Sw3. Sw1:e2 passa
         de Forwarding a Blocking.

  4. Tunnels & Overlay Networks
  (Arquivo: 4_Tunnels_OverlayNets_RCII_2026.pdf)

  Exemplo - Página 37
   * a) Entradas OSPF de R3:
       * Aprende todas as redes públicas e loopbacks. Ex: 10.2.2.2/32 (Lo de R2) com custo 2 (via R1 ou R4).
   * b) Percurso Ping 192.1.14.0/24 (R1) -> 192.2.35.0/24 (R3):
       * Request: R1 -> R3 (via OSPF direto).
       * Reply: R3 tem rota estática para 192.1.14.0/24 via Tunnel. O pacote é encapsulado e enviado para o IP de destino do túnel (R2). Percurso: R3 -> R1/R4 -> R2 (decapsula) -> R1.
   * c) Tráfego 192.2.35.0/24 <-> 192.3.66.0/24 usa o túnel?
       * Não. A rota estática em R3 é específica para a rede 192.1.14.0/24. Outros destinos seguem o caminho normal de OSPF.

  5. BGP
  (Arquivo: 5_BGP_RCII_2026.pdf)

  Exemplo - Página 36
   * a) Atributos de 195.10.0.0/24 (de R1 para R4):
       * AS_PATH: {150, 160}.
       * NEXT_HOP: 192.168.15.1 (IP de R1 no link eBGP).
   * b) Atributos de 192.4.4.0/24 (de R1 para R2):
       * AS_PATH: {140}. (iBGP não adiciona o próprio AS).
       * NEXT_HOP: 192.1.2.1 (IP interno de R1).
   * c) Percurso R3 -> 195.10.0.0/24:
       * R3 não tem BGP. Usa a Default Route anunciada por OSPF pelo R1.
       * Caminho: R3 -> R1 -> R2 (via iBGP) -> R5 (via eBGP).
   * d) Sucesso no Ping R3 -> 192.168.15.4:
       * Sim. R3 envia para R1 (Default Route). R1 está ligado diretamente a essa rede. R4 sabe voltar para R3 porque as redes OSPF do AS 150 foram redistribuídas no BGP.
